# CodeArts Agent Team 多智能体协作实操

> 语言：**简体中文** ｜ [English](agentteam_readme.md)
>
> 状态：进行中。准备清单、指令和记录表先落好，截图和数字跑完补。

Agent Team 是码道 Agent Space 里的多智能体协作引擎：一条需求发出去，Leader 负责拆任务、分派，多个 Teammate 像真实开发团队一样并行干活，从需求分析做到代码交付。2026 年 9 月上线，官方口径是全程无需人工干预。

演示时如果有人问「这不就是并行跑几个子智能体吗」，用这张表回答（来自官方文档的对比）：

| 维度 | 子智能体 | Agent Team |
| --- | --- | --- |
| 上下文 | 单次执行结束即销毁 | 持续驻留，跨任务保留对话与记忆 |
| 通信 | 只能把最终结果返回给父智能体 | 双向即时通信 |
| 任务管理 | 父智能体静态分配 | 共享任务池，Teammate 自主认领，Leader 动态调度 |
| 生命周期 | 随任务结束销毁 | 动态组建，按需增减成员 |
| 异常处理 | 失败只能向上抛出 | 成员异常时 Leader 重新分派或补位 |

## 1. 准备

1. 码道 IDE 升到最新版，登录华为云账号。
2. 打开本目录（1-agentteam-demo）作为工作区。
3. 切到 Space 模式，进「代码开发」页签，输入框上方的模式下拉框从「智能体」切成「AgentTeam」。
4. 模型避开 Deepseek V3.1，官方文档写明该模型暂不支持 Agent Team。
5. 全局设置里给对话流/智能体开自动批准。不开的话每个 Teammate 的敏感操作都会弹确认，「无需人工干预」的演示效果直接破功。
6. 看一眼积分余额。多智能体并行是成倍消耗，另有 5 小时/7 天双滑动窗口限流。

## 2. 发需求

用官方同款例子，一条指令同时包含调研和开发，天然展示多角色拆解：

```
开发一个睡眠质量记录小程序，开发前先分析国内现有的睡眠质量记录小程序产品并总结其优缺点，然后开发一款在当前市场上有竞争力的功能性小程序。
```

预期 Leader 会拆出市场分析、产品设计、前端开发之类的角色并行推进。量级 10 到 30 分钟，积分消耗中等。

## 3. 看拆解和并行

- 左侧任务分派图：拆出了哪些角色，谁创建、谁执行、上下游依赖。（待补截图）
- 任务概览：并行智能体数、总耗时、Token 用量，数字都是现成的量化素材。（待补截图）
- 点进单个 Teammate 的任务详情：实时看它改了哪些文件、上下文水位，支持暂停/恢复。（待补截图）

## 4. 收尾

- 编辑器里看 diff，逐个保留或撤销。
- 可选彩蛋：对话框输入 `/save-team`，把当前团队（Roles + Scene）存成模板，落在 `.codeartsdoer/agent-team/` 下。再用模板发一条变体需求（比如儿童哄睡小程序），展示秒级二开。

## 备选指令

前后端并行小项目，并行画面最直观，积分也省：

```
做一个待办事项 Web 应用，前端用 React，后端用 Express，数据存本地文件，带单元测试，前后端可以并行开发。
```

存量仓增量开发（进阶，官网给 Agent Team 的定位场景就是它）。跑之前先复制一份仓库到别处，别在原克隆里跑：

```
调研本仓库 consumer rebalance 的实现，写一份设计文档，指出一个可改进点并给出原型实现。
```

## 排坑

| 症状 | 处置 |
| --- | --- |
| 找不到 AgentTeam 模式 | 确认在 Space 模式的「代码开发」页签，IDE 是最新版 |
| 报模型不支持 | 换模型，Deepseek V3.1 暂不支持 |
| 执行中途反复弹确认 | 全局设置里给对话流/智能体开自动批准 |
| 跑到一半卡住 | 新开会话重试；日志在 `%USERPROFILE%\.codeartsdoer\codearts-data\log`，搜 `agent-team` 看各子智能体状态 |
| 积分突然见底 | 提前看余额，演示前用小需求试跑一轮 |
